好的，這是一個非常經典且常見的問題，尤其是在處理由 PowerPoint (PPT) 簡報轉換而來的 PDF 檔案時。您遇到的情況完全正常，我來為您詳細解釋原因以及提供解決方案。

問題的根本原因：PDF 的結構與 PPT 的轉換機制

簡單來說，您用 fitz (PyMuPDF) 的 page.get_images() 方法提取出來的，是存在於該 PDF 頁面資源庫 (Resource Library) 中的所有圖片物件。而您在頁面上「看到」的內容，只是這些資源被排版和渲染後的結果。

當一個 PPT 檔案被轉換成 PDF 時，會發生以下幾件事，這就導致了您遇到的問題：

  1. 母片 (Master Slide) 元素：PowerPoint 的母片通常包含背景圖片、公司 Logo、頁腳的圖示或分隔線等。在轉換成 PDF 時，這些母片上的圖片元素會被嵌入到每一個頁面的資源庫中，即使它們在視覺上只是背景。fitz 會忠實地將這些資源全部提取出來，所以您會得到很多重複的背景圖或 Logo。
  2. 隱藏或被覆蓋的圖片：在製作 PPT 時，使用者可能放置了一張圖片，後來又用另一張圖片或一個色塊將其完全覆蓋。在 PDF 中，被覆蓋的舊圖片資料通常仍然存在於檔案中，只是沒有被顯示出來。fitz 在掃描資源時，同樣會找到這個「隱藏」的圖片並將其提取。
  3. 小圖示與模板素材：簡報模板中可能包含一些預設的小圖示、按鈕圖案等。這些也都會被當作圖片資源儲存起來。
  4. 圖片的多個版本：有時 PDF 為了渲染效率，可能會儲存同一張圖片的低解析度預覽圖和高解析度原圖。get_images() 可能會將兩個版本都抓出來。

核心觀念： page.get_images() 做的是「資源提取」，而不是「畫面擷取」。它不分析畫面上哪個位置有圖，而是直接從 PDF 檔案的內部結構中，把所有被標記為「圖片」的資料物件 (Image XObjects) 拿出來。這就是為什麼您會拿到很多「頁面上沒有的」圖片，因為它們其實是背景、Logo 或被隱藏的元素。

如何解決：兩種有效的策略

針對這個問題，有兩種主要的解決策略，各有優劣。

策略一：【推薦】渲染後定位裁切 (Render and Crop) - 所見即所得

這個方法最直觀，也最符合您的需求：「我只想拿到眼睛看到的那些主要圖片」。

原理：我們不直接去猜哪些資源是我們想要的。而是先分析頁面上有哪些「繪圖物件」，找到那些看起來像圖片的物件的位置（邊界框 Bounding Box），然後像螢幕截圖一樣，只擷取那個區塊的影像。

PyMuPDF 的 page.get_drawings() 方法是實現這個策略的關鍵。

程式碼範例：

Python

import fitz  # PyMuPDF
import os

# 建立一個資料夾來存放擷取的圖片
output_dir = "extracted_visible_images"
os.makedirs(output_dir, exist_ok=True)

pdf_path = "your_presentation.pdf"
doc = fitz.open(pdf_path)

print(f"開始處理 PDF: {pdf_path}")

for page_num in range(len(doc)):
   page = doc.load_page(page_num)
   
   # get_drawings() 可以取得頁面上的所有向量圖形和圖片的繪製資訊
   drawings = page.get_drawings()
   
   # 我們可以透過一些條件來過濾出我們想要的圖片
   # 例如，圖片通常是 'f' (fill) 或 'i' (image) 類型的路徑
   # 這裡我們用一個更簡單的邏輯：找到較大的矩形區域並擷取
   
   image_count_per_page = 0
   for i, path in enumerate(drawings):
       # path['rect'] 是這個繪圖物件的邊界框
       rect = path["rect"]
       
       # 過濾掉太小的物件，這些可能是線條或小圖示
       # 您可以根據您的文件調整這個閾值
       if rect.width < 100 or rect.height < 100:
           continue
           
       # 過濾掉佔滿整個頁面的物件，這很可能是背景
       if rect.width > page.rect.width * 0.95 and rect.height > page.rect.height * 0.95:
           continue

       # 使用 get_pixmap 搭配 clip 參數，精確地只渲染這個矩形區域
       # 這就像是對這個區域進行螢幕截圖
       pix = page.get_pixmap(clip=rect)
       
       # 儲存圖片
       image_filename = f"{output_dir}/page{page_num+1}_img{image_count_per_page+1}.png"
       pix.save(image_filename)
       
       image_count_per_page += 1
       print(f"  > 在第 {page_num+1} 頁找到並儲存圖片: {image_filename}")

doc.close()
print(f"處理完成！圖片已儲存至 '{output_dir}' 資料夾。")

優點：

  • 準確性高：真正實現了「所見即所得」，只提取頁面上可見的、符合尺寸條件的圖片。
  • 忽略背景：可以輕鬆過濾掉全頁背景和微小圖示。

缺點：

  • 輸出格式：輸出的是渲染後的點陣圖 (如 PNG)，而不是原始的圖片格式 (如 JPEG)。
  • 可能需要調整：過濾條件（如寬高 100 或 0.95 的比例）可能需要根據具體 PDF 檔案進行微調。

策略二：過濾 get_images() 的結果

這個方法是基於您現有的做法進行改良。既然 get_images() 會拿出所有東西，那我們就加上智慧的過濾條件，把不要的篩掉。

原理：利用 get_images(full=True) 取得每張圖片的詳細資訊，如內部編號 (xref)、寬高、大小等，然後根據這些資訊來判斷是否為我們想要的圖片。

常見的過濾邏輯：

  1. 過濾重複圖片：母片上的 Logo 和背景在每一頁的 xref（交叉參照編號）通常是相同的。我們可以記錄已經提取過的 xref，不再重複提取。
  2. 過濾尺寸：根據圖片的寬和高來過濾。太小的可能是圖示，非常大的（接近頁面尺寸）可能是背景。

程式碼範例：

Python

import fitz
import os
from PIL import Image
import io

# 建立輸出資料夾
output_dir = "extracted_filtered_images"
os.makedirs(output_dir, exist_ok=True)

pdf_path = "your_presentation.pdf"
doc = fitz.open(pdf_path)

# 用一個集合 (set) 來存放已經處理過的圖片 xref，避免重複
processed_xrefs = set()

print(f"開始處理 PDF: {pdf_path}")

for page_num in range(len(doc)):
   page = doc.load_page(page_num)
   
   # 使用 full=True 來取得包含 xref 的詳細圖片列表
   image_list = page.get_images(full=True)
   
   # 取得頁面尺寸，用於判斷背景圖
   page_w, page_h = page.rect.width, page.rect.height
   
   if not image_list:
       continue
       
   print(f"在第 {page_num+1} 頁找到 {len(image_list)} 個圖片資源...")

   for img_index, img_info in enumerate(image_list):
       xref = img_info[0]
       
       # 1. 過濾重複的圖片 (通常是母片元素)
       if xref in processed_xrefs:
           # print(f"  - 跳過重複的圖片 (xref: {xref})")
           continue
       
       # 提取原始圖片數據
       base_image = doc.extract_image(xref)
       image_bytes = base_image["image"]
       
       # 2. 透過尺寸過濾
       try:
           pil_image = Image.open(io.BytesIO(image_bytes))
           width, height = pil_image.size
       except Exception:
           # 有些圖片格式 PIL 可能不認識，直接跳過
           continue
       
       # 過濾掉太小的圖片（可能是圖示）
       if width < 100 or height < 100:
           # print(f"  - 跳過太小的圖片 (xref: {xref}, size: {width}x{height})")
           continue
           
       # 過濾掉接近頁面大小的圖片（可能是背景）
       # 注意：圖片的解析度可能和 PDF 頁面的點(pt)單位不同，這裡做個大概的比例判斷
       # 這個判斷比較粗略，策略一更準確
       if width > page_w * 0.9 and height > page_h * 0.9:
           # print(f"  - 跳過背景圖片 (xref: {xref}, size: {width}x{height})")
           continue
       
       # 如果通過所有過濾，就儲存它
       image_ext = base_image["ext"]
       image_filename = f"{output_dir}/page{page_num+1}_xref{xref}.{image_ext}"
       with open(image_filename, "wb") as f:
           f.write(image_bytes)
           
       print(f"  > 找到並儲存有效圖片: {image_filename}")
           
       # 標記此 xref 已處理
       processed_xrefs.add(xref)

doc.close()
print(f"處理完成！圖片已儲存至 '{output_dir}' 資料夾。")

優點：

  • 保留原始格式：可以提取出原始的 JPEG/PNG 等格式，檔案可能更小，品質也未經二次渲染。
  • 效率可能更高：如果過濾規則簡單有效，可以避免渲染整個頁面的開銷。

缺點：

  • 過濾規則不通用：過濾條件（如尺寸、重複性）對於某些特殊的 PDF 可能會失效，例如，某個重要的圖片恰好尺寸很小。
  • 無法處理被覆蓋的圖片：如果一張不想關的圖片被覆蓋，但它尺寸又「正常」，這個策略可能還是會把它提取出來。

對於您「從PPT轉來的PDF」這種情況，我強烈推薦您優先嘗試【策略一】。因為它最能解決「拿到一堆背景和Logo」這個核心痛點，結果也最符合直覺。您可以先用策略一的程式碼跑一次看看效果，如果效果良好，再根據需要看是否要優化過濾的尺寸條件。
